Sutra सूत्र

A deep-learning framework I wrote from scratch in NumPy, and two models it trained that you can try below.

Onkar Dange · September 2026 · source on GitHub

When you call loss.backward() in PyTorch, a lot happens that you never see. I wanted to see all of it, so I wrote the whole stack myself: a tensor that remembers how it was computed, a hand-derived backward pass for every layer, the optimizers, a tokenizer and int8 quantisation. The only library it imports is NumPy.

Then I used it to train real models. One is a small convolutional network that reads handwritten digits. The other is a 2.7M-parameter GPT that writes in the style of Shakespeare. Both run on this page, in your browser, on a 244-line JavaScript engine I wrote for them.

2.Write some Shakespeare

This is a 6-layer, 6-head, 192-wide character-level GPT trained on about a million characters of Shakespeare. It has only ever seen single characters, never words. Everything it knows about names, line breaks and old spellings, it picked up by learning to predict the next character.

Give it an opening and let it continue. Temperature controls how adventurous it is: near 0 it repeats itself, and above 1 it starts inventing words. Once it has written something, hover over any character to see what the model was looking at when it chose that character. The highlighter marks how much attention each earlier character got.

3.Does it actually work?

        
A framework can be slightly wrong and still train, just worse, without ever raising an error. So I checked it in two ways. First, 207 tests run each operation in both Sutra and PyTorch on the same inputs, and require the values and the gradients to agree to about seven decimal places. When I planted small bugs in the backward passes on purpose, the tests caught every one.

        
Second, I used it to run proper experiments. Each one uses a held-out validation split and several random seeds per setting, and reports 95% confidence intervals. Every curve below comes from a model trained with Sutra on a laptop CPU.

        

      

      

    

  


  

    

      

        
4.How it's built

        
Every operation returns a new tensor that remembers its inputs, plus a small function that turns the gradient of its output into gradients for those inputs. Calling backward() sorts that graph with an explicit stack, not recursion, so very deep graphs work. It then runs those functions in reverse. The slow parts (convolution, attention, the norms and cross-entropy) each get a single fused backward pass that I derived by hand.

  2. functional.pyconv2d as one matrix multiply (im2col), pooling, fused attention, LayerNorm, BatchNorm, softmax, and cross-entropy with label smoothing.

  3. nn.pyModules with parameter registration, buffers, state dicts, train/eval modes, and the standard layers.

  4. optim.pySGD with Nesterov momentum, Adam, AdamW and RMSprop, plus gradient clipping and cosine warmup. They match torch.optim step for step.

Training code reads almost exactly like PyTorch:


import sutra as st
from sutra import nn, optim, F

model = nn.Sequential(
    nn.Conv2d(1, 16, 3, padding=1),
    nn.BatchNorm2d(16), nn.ReLU(),
    nn.MaxPool2d(2), nn.Flatten(),
    nn.Linear(16 * 14 * 14, 10))
opt = optim.AdamW(model.parameters(), 3e-3)

for x, y in loader:
    loss = F.cross_entropy(model(x), y)
    opt.zero_grad()
    loss.backward()        # reverse-mode autodiff
    opt.step()

# the fused attention backward, derived by hand:
# dV = Pᵀ·dO     dP = dO·Vᵀ
# dS = P ⊙ (dP − rowsum(dP ⊙ P))
# dQ = dS·K/√d   dK = dSᵀ·Q/√d

        
It runs on the CPU only and is slower than PyTorch. The speed comparison is in the last figure above. It was built to be understood and checked, not to be fast. If you are new to all this, there is also a plain-language explanation of the whole project.
